# Task 1 — buyer/account UX: карта и передача

**Фактическая база:** `feat/product-ready-tenant-foundation-2026-11-23` @ `41e47ec`
(включает контрольную точку задания `46d2a4e` и завершённый поток A `bf3b0d1`).
Работа выполнена в отдельной feature-ветке, не в общей.

## 1. Карта работающего UX (проверено по коду, не переписывалось)

- **Account/Auth:** вход и регистрация через Supabase Auth, загрузка/пустое состояние,
  безопасные сообщения об ошибках, sign-out, восстановление пароля и явная форма
  нового пароля (`PASSWORD_RECOVERY` + synchronous URL-intent).
- **Организации и роли:** выбор своей организации, список участников и приглашения,
  owner/admin-управление ролями, читаемые подписи ролей, read-only бейдж `viewer`.
  Серверная проверка — RLS/grants/RPC, UI не является границей доступа.
- **Buyer path:** каталог, списки закупок, черновые корзины, выбор локации,
  изменение количества, reload/persist, review с причинами блокировки,
  атомарная идемпотентная отправка `submitted` request. Успех явно не называется
  принятым заказом; повтор с тем же ключом не создаёт дубль.
- **Мобильный путь:** E2E на 390px, проверка горизонтального overflow,
  desktop + mobile Proposition, axe WCAG 2.1 A/AA gate.
- **Demo vs account:** разные маршруты и баннеры; демо-персоны не используются
  для авторизации в account-пути.

## 2. Что сделано в этом задании

- **Локации покупателя:** добавлены безопасные `updateBuyerLocation` и
  `deleteBuyerLocation` в adapter. Обновляются только разрешённые grants колонки
  (`name`, `address`, `delivery_zone`) с фильтром `organization_id`.
  Удаление перед записью проверяет отсутствие ссылок в `buyer_draft_carts` и
  `buyer_procurement_requests` (оба FK — `ON DELETE RESTRICT`) и возвращает
  типизированную ошибку `location_in_use` с понятным сообщением. Гонку
  между проверкой и удалением по-прежнему ловит база; пользователь видит
  безопасную ошибку, а не внутренний SQL.
- **UI:** кнопки «Изменить точку» / «Удалить точку» только для owner/admin,
  форма редактирования с предзаполнением, подтверждение удаления, отмена,
  понятные success/error состояния. Viewer не видит этих действий.
- **Тесты:** 4 новых адаптерных теста (запись только разрешённых колонок, отказ
  невалидного ввода, отказ при использовании и удаление неиспользуемой точки). Ни один серверный контракт
  не изменён: миграции, RLS, RPC и `database.types.ts` не трогались.

## 3. Остаточные пробелы и предложенные зависимости (РЕШЕНИЕ НЕ ПРИНЯТО)

### 3.1 Точные причины отказа приглашения — нужна capability Кодера C

Сейчас `accept_organization_invitation` возвращает `NULL` для истёкшей, отозванной,
уже использованной ссылки и для несовпадения email. Клиент не может различить
причины, не гадая; UI использует общую actionable-копию.

**Предлагаемый контракт (не реализован):** RPC `describe_organization_invitation`
по хешу токена, read-only, без мутаций, возвращает перечисление
`valid | expired | revoked | accepted | email_mismatch | not_found` и `expires_at`;
`accept_organization_invitation` может вернуть тот же код причины. Политики
RLS — только аутентифицированный пользователь, никакого раскрытия чужого email.
Пока контракта нет, клиентская классификация была бы имитацией — не сделана.

### 3.2 Удаление аккаунта/организации и retention — решение владельца

Сейчас отсутствует. Наивное удаление невозможно: `organizations.created_by` и
`invitations.invited_by` объявлены `ON DELETE RESTRICT`; неизменяемые снимки
запросов и приватные подзаказы требуют отдельного срока хранения.

**Варианты (выбор за владельцем):** (а) пока не реализовывать, зафиксировать
отсутствие в UI/документации; (б) спроектировать передачу владения + архивацию
организации с политикой хранения; (в) полное удаление с каскадом и явным
списком удаляемых данных. Блокеры: юридический оператор, сроки хранения,
владелец снимков/подзаказов, поведение `auth.users`. Ни один вариант не выбран
и не внедрён.

### 3.3 Казахская локализация — решение по пилоту

Сейчас `kk` — алиас `ru`; аккаунт-строки хардкод русского.

**Варианты:** (а) оставить русский как язык пилота; (б) сделать полный `kk`
словарь и ревью терминологии носителем языка. Блокер: владелец не выбрал
город/сегмент пилота и язык интерфейса. Локализация не изменена.
