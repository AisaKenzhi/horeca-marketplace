# STOCK-01 — модель доступности (локальный default)

**Решение агента (обратимое, по разрешению владельца работать без вопросов):** `availability` — **наблюдение поставщика** с отдельной меткой времени, без числового остатка, резерва и гарантии покупки. `in_stock` не означает физический складской остаток. Реальная модель запаса/резерва — решение владельца и поставщиков, здесь не выбирается.

## Текущая state table

| Значение          | Что означает в прототипе                         | Что НЕ означает                                       |
| ----------------- | ------------------------------------------------ | ----------------------------------------------------- |
| `in_stock`        | поставщик сообщил о наличии на момент наблюдения | резерв, гарантированное количество,физический остаток |
| `low_stock`       | поставщик сообщил «мало» без числа               | точный остаток или auto-reorder                       |
| `out_of_stock`    | поставщик сообщил об отсутствии                  | запрет на будущие повторные проверки                  |
| `on_request`      | требуется уточнение поставщика                   | подтверждённое предложение                            |
| `unknown` / stale | данные неизвестны или устарели                   | актуальное наличие                                    |

Любое устаревшее или неизвестное значение блокирует отправку buyer request или требует явного повторного подтверждения (существующая серверная проверка). Наблюдение availability хранится отдельно от цены.

## Открытые вопросы владельцу (не выбраны агентом)

1. Достаточно ли подтверждения поставщика или нужен резерв с TTL?
2. Кто владеет резервом, каковы capacity, release и oversell-правила?
3. Как часто поставщик обновляет наблюдение и какой срок свежести считать корректным?
4. Как обрабатывать частичное принятие и отмену резерва?
